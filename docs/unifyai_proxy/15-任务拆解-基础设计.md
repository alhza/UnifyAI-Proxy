## 设计决策清单（默认值/策略）

### 核心概念定义
- **account-limits（账户限额）**：每个账户的**固定配额上限**，由配置文件定义，包括日请求数(daily.requests)、日Token数(daily.tokens)、每分钟请求数(rate.rpm)。系统根据此限额跟踪账户使用量(Usage)。`reset-timezone`（若配置）用于计算每日重置时刻（默认 UTC）。
- **quota-exceeded（配额耗尽策略）**：当账户达到 account-limits 限额或状态机进入 QuotaExceeded 状态时的**行为策略**，包括是否切换账户(switch-project)、是否回退到 preview 模型(switch-preview-model)。
- **状态机(State Machine)**：账户运行时状态，包括 Available(可用)、CoolingDown(冷却中)、QuotaExceeded(配额耗尽)、Errored(错误)，状态转换由 account-limits 限额检查、错误类型、冷却时间等因素触发。

### 策略决策
- 路由策略：启用模型别名/黑名单；`force-model-prefix` 默认关闭；能力校验（多模态/Tool Calling/上下文长度）默认开启，不满足时拒绝；预览模型回退默认开启。
- **限额/状态机策略**：
  - **状态枚举**: Available/CoolingDown/QuotaExceeded/Errored
  - **重置时钟与时区**：
    - 默认使用 **UTC 日界**(00:00 UTC)作为全局统一重置时间，避免多账户时区不一致问题
    - 支持通过配置 `account-limits.reset-timezone` 覆盖(如 `America/Los_Angeles` for PST)
    - 不同 Provider 的官方重置时间参考(仅供对齐，系统默认 UTC)：
      - Claude: UTC 日界
      - Gemini: UTC 日界  
      - Codex: PST 日界(UTC-8/UTC-7 夏令时)
    - 每日限额重置时刻 = `时区日界00:00` 转换为 UTC 时间戳存储在 ResetAt
    - RPM 限额使用滑动窗口，不受日界影响
  - **冷却时间**: 由 `max-retry-interval` 控制上限(秒)；冷却期间 UnavailableUntil 存储恢复时间戳。
- **全账号不可用错误码策略**：
  - **429 Too Many Requests**: 当所有账户因配额耗尽(QuotaExceeded)而不可用时返回，响应包含 `Retry-After` 头(最近的 resetAt 时间戳)和详细错误信息(下次重置时间)。
  - **503 Service Unavailable**: 当所有账户因错误状态(Errored)、冷却(CoolingDown)或系统故障而不可用且无明确恢复时间时返回，响应包含 `Retry-After: 60`(建议1分钟后重试)。
  - **判定逻辑**: 优先检查是否有 QuotaExceeded 状态的账户，若有则返回 429 + 最近 resetAt；否则返回 503。
- 重试与切换：对 403/408/429/5xx 按 `request-retry` 重试，单账号不自旋，失败则切换选路策略（轮询/fill-first）；遵循 quota-exceeded 策略决定是否切换账户或模型。
- **SSE 流式策略**：
  - **事件映射**: 将各 Provider 的 SSE 事件映射为 OpenAI `data: {...}` 格式；流结束发送 `data: [DONE]`。
  - **错误中断**: 接收到错误事件或上游断开连接时，立即发送错误事件并关闭流；不继续发送 `[DONE]`。
  - **客户端断开检测**: 通过 `http.CloseNotifier` 或 `context.Done()` 检测客户端断开；检测到后立即取消上游请求并清理资源；每次写入前检查连接状态。
  - **Keepalive 心跳**: 配置 `streaming.keepalive-seconds`(默认0=关闭)；开启时每N秒发送 `: keepalive\n\n` 注释行保持连接；仅在无数据块发送时触发。
  - **Bootstrap 重试**: 配置 `streaming.bootstrap-retries`(默认0=关闭)；首包接收前的上游失败自动重试N次(切换账户)；首包接收后不再重试，直接传递错误；防止客户端长时间等待。
  - **并发安全**: 写入 ResponseWriter 需加锁；Flusher.Flush() 调用需原子执行。
  - **Tool Calling 流式处理**：
    - **调用 ID 生成**: 首次接收到 tool_call 增量时生成稳定 ID(如 `call_<uuid>`)；后续该调用的增量复用相同 ID。
    - **增量参数累积**: 维护每个 tool_call ID 的参数缓冲区(string builder)；接收到参数片段时追加到缓冲区；Provider 返回格式不同时(如 Gemini 完整参数 vs Claude 增量)需规范化为 OpenAI 增量格式。
    - **并行调用处理**: 支持多个 tool_call 并行流式输出；使用 map[callID]*CallState 跟踪每个调用状态(name/args buffer/index)；按接收顺序分配 index(0,1,2...)。
    - **流终止清理**: `[DONE]` 前验证所有 tool_call 参数完整(valid JSON)；错误中断时清理所有 CallState；记录未完成调用的警告日志。
    - **错误恢复**: 单个 tool_call 参数解析失败时标记该调用为 error，继续处理其他调用；全部失败时中断流并返回错误事件。
- **安全/运维策略**：
  - **管理端安全**: 默认仅本地访问；必须配置密钥(bcrypt 哈希存储，不存明文)；面板可选禁用。
  - **TLS/反代**: 支持 TLS 直接终止或反向代理(推荐 Nginx/Caddy)；反代模式下信任 X-Forwarded-* 头。
  - **日志脱敏规则**（必须实现的敏感字段掩码）：
    - OAuth Tokens: `access_token`/`refresh_token`/`id_token` → 仅记录前8后4字符，中间用 `***` 替换(如 `sk-ant-o***-1234`)
    - API Keys: `api_key`/`apiKey` 字段 → 同 token 规则
    - HTTP Headers: `Authorization`/`X-API-Key`/`Cookie` → 完全掩码为 `[REDACTED]`
    - OAuth 参数: `client_secret`/`code_verifier`/`code` → 完全掩码
    - 配置敏感字段: `secret-key`/`password` → 不记录到日志文件
    - URL 参数: 查询字符串中的 `token`/`key`/`secret` 参数 → 掩码
  - **日志管理**: 文件上限受 `logs-max-total-size-mb` 控制(0=不限)；超限时删除最旧日志；权限设置 640；支持日志采样(可配置采样率)。
  - **可观测性**: `/health` 端点(存活检查)；`/metrics` 端点(Prometheus 格式，需 ACL 保护)；必备指标(请求计数/延迟/账户状态/配额使用)。
- **配置热更新策略**：
  - **监听机制**: 使用 fsnotify 监听配置文件变化；检测到修改事件后延迟500ms触发重载(防抖)。
  - **版本管理**: 每次配置加载生成递增版本号(atomic.Uint64)；请求开始时读取版本快照，处理期间使用该版本配置；配置对象使用 atomic.Value 存储，读取无锁。
  - **并发控制**: 配置重载时创建新配置对象，原子替换 atomic.Value；旧配置引用计数递减至0后回收；正在进行的请求继续使用旧版本配置，不受影响。
  - **刷新范围**: 更新模型映射/黑名单、账号限额配置、代理设置、日志级别；不刷新 server.port/tls 等需重启的配置。
  - **连接保护**: 不强制断开现有 SSE/WS 连接；新请求使用新配置；账号表状态机保持，仅更新限额阈值。
  - **失败处理**: 配置解析失败时保持当前配置不变，记录错误日志；每次重载验证配置完整性(必填字段、类型校验、模型别名冲突检测)。
  - **模型别名冲突检测**：
    - **循环引用检测**: 使用深度优先搜索(DFS)检测别名链中的循环(如 `a→b→c→a`)；发现循环时拒绝配置加载。
    - **多级别名展开**: 支持别名链(如 `gpt-4 → claude-sonnet → claude-sonnet-4-5-20250929`)，但限制最大展开深度为5级，防止无限递归。
    - **通配符冲突**: 检测通配符别名(如 `gpt-*`)与精确别名(如 `gpt-4`)的冲突；精确别名优先级高于通配符；多个通配符匹配时选择最长前缀。
    - **黑名单优先**: 黑名单检查在别名展开之前执行；被黑名单屏蔽的模型不可通过别名访问。
    - **验证规则**: 启动和热更新时执行验证；验证失败时记录详细错误(冲突的别名对)并拒绝配置；提供 `/config/validate` 管理端点供手动验证。

## 核心接口/结构草案（建议路径）
- Config 结构（`internal/config`）：
  - server/tls/remote-management/auth/providers/logging/logging-to-file/logs-max-total-size-mb/commercial-mode/proxy-url/routing/quota-exceeded/streaming/account-limits/openai-compatibility/vertex-api-key/ampcode/payload/model-mapping/blacklist/force-model-prefix。
- Account 状态机（`internal/account` 或 `internal/quota`）：
  - **状态字段**：State(Available|CoolingDown|QuotaExceeded|Errored)、UnavailableUntil、ResetAt、Usage(ReqCount/TokenCount/RPM)、LastError。
  - **重置时钟**：默认 UTC 日界(00:00 UTC)，可配置时区；超额返回信息包含最近 resetAt。
  - **状态转换规则**（需原子操作，加锁保护）：
    - `Available → QuotaExceeded`: 当 Usage 超过 account-limits 时触发；设置 ResetAt 为下一个重置时间点。
    - `Available → CoolingDown`: 当请求失败(403/429/5xx)且重试次数未超 request-retry 时触发；设置 UnavailableUntil = now + min(backoff, max-retry-interval)。
    - `Available → Errored`: 当遇到致命错误(401/网络错误)或重试耗尽时触发；记录 LastError。
    - `CoolingDown → Available`: 当 now >= UnavailableUntil 且 Usage 未超限时自动恢复。
    - `QuotaExceeded → Available`: 当 now >= ResetAt 时自动恢复并重置 Usage 计数器。
    - `Errored → Available`: 需手动干预或配置的恢复策略(如定时探测)。
  - **并发控制**：状态转换使用 RWMutex；MarkResult 操作需写锁；Pick 操作需读锁；Token 刷新使用双重检查锁定模式(避免闭包陷阱，刷新后重新获取账户引用)。
  - **重置机制**：后台 goroutine 定时检查(每分钟)，对所有账户检查 ResetAt/UnavailableUntil，触发状态转换和 Usage 清零；重置时发出事件供 metrics 记录。
- AccountSelector 接口（`internal/account`）：
  ```go
  // Result 封装请求结果，用于状态更新
  type Result struct {
      Success       bool
      ErrorType     ErrorType  // 错误类型(QuotaExceeded/RateLimited/AuthError/NetworkError/ServerError)
      ErrorCode     int        // HTTP 状态码(403/429/503等)
      TokensUsed    int64      // 使用的 Token 数
      ResponseTime  time.Duration
      ShouldRetry   bool       // 是否应该重试
      ShouldSwitch  bool       // 是否应该切换账户
  }
  
  // ErrorType 错误类型枚举
  type ErrorType int
  const (
      ErrorTypeNone ErrorType = iota
      ErrorTypeQuotaExceeded   // 配额耗尽
      ErrorTypeRateLimited     // 速率限制
      ErrorTypeAuthError       // 认证错误(401/403)
      ErrorTypeNetworkError    // 网络错误
      ErrorTypeServerError     // 服务器错误(5xx)
  )
  
  type AccountSelector interface {
      Pick(model, provider string) (*Account, error)
      MarkResult(acc *Account, result Result) // 包含错误类型/用量，需要原子更新状态
  }
  ```
- RateLimiter/QuotaCounter（`internal/quota`）：
  ```go
  // QuotaState 配额状态枚举
  type QuotaState int
  const (
      QuotaStateOK QuotaState = iota
      QuotaStateNearLimit      // 接近限额(>80%)
      QuotaStateExceeded       // 超过限额
      QuotaStateRateLimited    // 速率限制触发
  )
  
  type RateLimiter interface { 
      Allow(ctx context.Context, key string) error 
  }
  
  type QuotaCounter interface {
      Add(acc *Account, reqs, tokens int64) QuotaState
      Reset(now time.Time)
      Check(acc *Account) QuotaState  // 检查当前配额状态
  }
  ```
- Provider 接口（`internal/provider`）：
  ```go

  type Provider interface {

  type OAuthConfig struct {
  ```
