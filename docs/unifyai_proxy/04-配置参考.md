# UnifyAI Proxy 配置参考

## 完整配置示例

```yaml
# config.yaml - 完整配置参考

# 服务器配置
server:
  host: 127.0.0.1          # 绑定地址
  port: 8317               # 监听端口
  allow-remote: false      # 是否允许远程访问管理界面
  secret-key: "your-strong-password"  # 管理界面密码

# 认证配置
auth:
  providers:
    - type: api-key
      api-keys:
        - my-secure-client-key
        - team-member-key

# 网络与重试
request-retry: 3           # 针对 403/408/5xx 的重试次数
max-retry-interval: 30     # 冷却期上限（秒）

# 模型映射
model-mapping:
  # OpenAI 模型别名 → 实际模型
  gpt-4: claude-sonnet-4-5-20250929
  gpt-4o: gemini-2.5-pro
  gpt-4-turbo: claude-opus-4-20250514

# 日志配置
logging:
  level: info              # debug, info, warn, error
  directory: ./logs
```

## 高级配置选项（对齐 CLIProxyAPI）

```yaml
# 传输与管理安全
tls:
  enable: false
  cert: ""
  key: ""
remote-management:
  allow-remote: false              # 默认仅本地访问管理接口
  secret-key: ""                   # 管理密钥，可存明文，启动时哈希
  disable-control-panel: false     # 是否禁用内置管理面板静态资源
  panel-github-repository: "https://github.com/router-for-me/Cli-Proxy-API-Management-Center"

# OAuth 凭证存储
auth-dir: "~/.unifyai-proxy/auths"  # OAuth token 存储目录，权限自动设为 700

# 日志与性能
logging-to-file: false
logs-max-total-size-mb: 0          # 0 关闭上限，>0 超限删旧
commercial-mode: false             # 关闭高开销中间件以降内存
usage-statistics-enabled: false    # 是否启用使用统计

# 网络与重试
proxy-url: ""                      # 全局代理，支持 socks5/http/https
request-retry: 3                   # 针对 403/408/5xx 的重试次数
max-retry-interval: 30             # 冷却期上限（秒）

# 配额耗尽策略（Quota Exceeded Behavior）
# 当账户达到 account-limits 限额或进入 QuotaExceeded 状态时的行为策略
quota-exceeded:
  switch-project: true             # 配额耗尽自动切换账号
  switch-preview-model: true       # 回退到 preview 模型
routing:
  strategy: "round-robin"          # round-robin 或 fill-first

# 流式
streaming:
  keepalive-seconds: 15            # SSE 心跳；<=0 关闭
  bootstrap-retries: 1             # 首包前的安全重试

# 模型控制（OAuth 渠道）
oauth-model-mappings:
  claude:
    - name: "claude-sonnet-4-5-20250929"
      alias: "cs4.5"
oauth-excluded-models:
  claude:
    - "claude-3-5-haiku-20241022"

# 请求 payload 规则
payload:
  default:   # 缺省时补充
    - models:
        - name: "gemini-2.5-pro"
          protocol: "gemini"
      params:
        "generationConfig.thinkingConfig.thinkingBudget": 32768
  override:  # 强制覆盖
    - models:
        - name: "gpt-*"
          protocol: "codex"
      params:
        "reasoning.effort": "high"

# 账户限额（Account Limits）
# 定义每个账户的固定配额上限，系统据此跟踪使用量并触发状态转换
account-limits:
  reset-timezone: "UTC"     # 限额重置时区，默认UTC，可设置为America/Los_Angeles等
  default:
    daily:
      requests: 5000        # 日请求上限
      tokens: 5000000       # 日 token 上限（无 usage 时可为空或不用）
    rate:
      rpm: 120              # 每分钟请求上限
  providers:
    claude:
      daily:
        requests: 3000
      rate:
        rpm: 60
    gemini:
      daily:
        tokens: 3000000
      rate:
        rpm: 90
  # 可选：对特定账号覆盖
  # overrides:
  #   - id: "account-1"
  #     daily:
  #       requests: 1000
  #     rate:
  #       rpm: 30

# API Key 直连配置（跳过 OAuth，直接使用 API Key）
# Gemini API Key 配置
gemini-api-key:
  - api-key: "YOUR_GEMINI_API_KEY"
    prefix: ""                      # 可选的模型名前缀
    base-url: ""                    # 可选自定义 API 端点
    headers: {}                     # 可选额外 HTTP 头
    proxy-url: ""                   # 可选代理配置
    models: []                      # 可选限制可用模型列表
    excluded-models: []             # 可选排除的模型列表

# Claude API Key 配置
claude-api-key:
  - api-key: "YOUR_CLAUDE_API_KEY"
    prefix: ""
    base-url: ""
    headers: {}
    proxy-url: ""
    models: []
    excluded-models: []

# Codex API Key 配置
codex-api-key:
  - api-key: "YOUR_CODEX_API_KEY"
    prefix: ""
    base-url: ""
    headers: {}
    proxy-url: ""
    models: []
    excluded-models: []

# Vertex AI 配置
vertex-api-key:
  - api-key: "YOUR_VERTEX_CREDENTIAL_JSON"
    prefix: ""
    base-url: ""
    headers: {}
    proxy-url: ""
    models: []

# OpenAI 兼容上游配置
openai-compatibility:
  - name: "custom-provider"
    prefix: "custom/"              # 模型名前缀
    base-url: "https://api.example.com/v1"
    headers:
      X-Custom-Header: "value"
    api-key-entries:               # 支持多个 API Key
      - "key1"
      - "key2"
    models:                        # 支持的模型列表
      - "gpt-4"
      - "gpt-3.5-turbo"
```

**如何使用这些高级项**
- 生产环境建议开启 `tls` 或通过反向代理终端 TLS，管理端点默认仅本地；`secret-key` 启动后会被哈希，避免明文存储。
- `logging-to-file` 搭配 `logs-max-total-size-mb` 控制磁盘占用，`commercial-mode` 适合高并发降开销。
- `routing.strategy` 支持按轮询或“填满再切换”；`quota-exceeded` 允许在配额耗尽时自动换账号或降级 preview。
- `streaming` 保障 SSE 链接在弱网下更稳；`request-retry/max-retry-interval` 处理短暂 5xx/限流。
- `oauth-model-mappings`/`oauth-excluded-models` 用于限制或重命名 OAuth 渠道模型，避免误用；`payload` 规则可按协议/模型注入或覆盖请求参数。
- `account-limits` 用于 per-account 配额/速率控制：达到每日上限或 RPM 上限时将账号标记不可用（直到重置或冷却），路由切换到其他账号；tokens 需要 Provider usage 字段，缺失时可仅按请求数限额。

## 配置项详解

### 服务器配置

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `server.host` | string | `127.0.0.1` | 绑定地址，`0.0.0.0` 允许外部访问 |
| `server.port` | int | `8317` | 监听端口 |
| `server.allow-remote` | bool | `false` | 是否允许远程访问管理界面 |
| `server.secret-key` | string | - | 管理界面密码 |

### 认证配置

| 参数 | 类型 | 说明 |
|------|------|------|
| `auth.providers` | array | 认证提供者列表 |
| `auth.providers[].type` | string | 认证类型，如 `api-key` |
| `auth.providers[].api-keys` | array | API key 白名单 |

### 网络与重试

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `request-retry` | int | `3` | 针对 403/408/5xx 的重试次数 |
| `max-retry-interval` | int | `30` | 冷却期上限（秒）|

### 配额耗尽策略

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `quota-exceeded.switch-project` | bool | `true` | 配额耗尽时自动切换账户 |
| `quota-exceeded.switch-preview-model` | bool | `true` | 回退到 preview 模型 |

### 模型映射

```yaml
model-mapping:
  <别名>: <实际模型名>
```

## Docker Compose 部署

```yaml
version: '3.8'
services:
  cliproxyapi:
    image: ghcr.io/router-for-me/cliproxyapi:latest
    container_name: cliproxyapi
    restart: unless-stopped
    ports:
      - "8317:8317"
    volumes:
      - ./config.yaml:/app/config.yaml:ro
      - ./auths:/root/.cli-proxy-api/auths
    environment:
      - TZ=Asia/Shanghai
```

### 使用步骤

```bash
# 1. 创建配置文件
touch config.yaml

# 2. 启动容器
docker compose up -d

# 3. 进入容器进行 OAuth 登录
docker exec -it cliproxyapi cli-proxy-api --claude-login
```

## Systemd 服务配置

```ini
# /etc/systemd/system/cli-proxy-api.service
[Unit]
Description=CLI Proxy API Service
After=network.target

[Service]
Type=simple
User=your-user
WorkingDirectory=/opt/cliproxyapi
ExecStart=/opt/cliproxyapi/cli-proxy-api --config /opt/cliproxyapi/config.yaml
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

### 使用步骤

```bash
# 1. 复制服务文件
sudo cp cli-proxy-api.service /etc/systemd/system/

# 2. 重载 systemd
sudo systemctl daemon-reload

# 3. 启用并启动服务
sudo systemctl enable cli-proxy-api
sudo systemctl start cli-proxy-api

# 4. 查看状态
sudo systemctl status cli-proxy-api
```

## 运维与安全加固

- **TLS/反向代理**：推荐用 Nginx/Caddy 终止 TLS，反代到本地端口；仅在反代内网开放管理端口，外网只暴露 `/v1/*`。
- **防火墙/访问控制**：生产环境固定 `server.host=127.0.0.1`，用防火墙或隧道（SSH、Cloudflared）暴露；管理界面 `/management.html` 仅限内网或隧道访问。
- **密钥管理**：`secret-key` 和 API keys 放入环境变量或秘密管理器，避免写死在配置文件；生产不要把配置挂只读 volume 之外的位置。
- **日志与脱敏**：启用日志目录后，注意脱敏 Authorization 头和 token 片段；设置日志轮转（按大小或时间），并限制权限 `chmod 640 logs/*`。
- **多实例/扩展**：可在反向代理层做负载均衡；token 存储默认为本地文件，若多实例部署需共享或同步 `~/.cli-proxy-api/auths/`，并确保文件权限一致。
- **健康检查与指标**：`/health` 作存活检查，`/metrics` 暴露基本运行指标（需结合反代或 ACL 限制可见范围）。
