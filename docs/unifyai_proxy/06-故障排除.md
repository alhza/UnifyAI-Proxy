# UnifyAI Proxy 故障排除

## 常见错误

| 错误 | 原因 | 解决方案 |
|------|------|----------|
| `HTTP 401` | Token 过期或无效 | 重新执行 `--claude-login` |
| `HTTP 404 Model not found` | 模型名称错误 | 检查 model-mapping 配置 |
| `Connection refused` | 服务未启动或端口错误 | 检查服务状态和端口配置 |
| `Address in use` | 端口被占用 | 更换端口或停止占用进程 |
| `Token unavailable` | 未登录或凭证丢失 | 重新执行登录命令 |

## 系统化排障流程

1. **连通性**：`curl http://127.0.0.1:8317/health` 是否 200；若失败检查进程/端口占用、防火墙/反代。
2. **认证**：确认客户端传入的 API key（若启用）正确；本地 `~/.cli-proxy-api/auths/` 是否存在对应 provider 的 token 文件，权限 `600`。
3. **模型映射**：请求中的 model 是否在 `model-mapping` 或 provider 列表中；若 404/422，检查映射表。
4. **日志**：开启 `--debug` 或配置 `logging.level=debug`，查看 `logs/`；注意脱敏 Authorization 头。
5. **Provider 健康**：同样的请求直接用官方 CLI/SDK 测试，确认官方服务可用且账户额度未耗尽。
6. **网络代理**：若部署在有出口代理环境，确认代理允许访问目标官方域名（Claude/Gemini/OpenAI/Qwen）。

## 详细排查

### HTTP 401 Unauthorized

**症状：**
```json
{"error": {"message": "Invalid API key", "type": "authentication_error"}}
```

**可能原因：**
1. OAuth token 已过期
2. 未完成登录认证
3. 凭证文件损坏

**解决方案：**
```bash
# 重新登录
cli-proxy-api --claude-login

# 检查凭证文件
cat ~/.cli-proxy-api/auths/claude/default.json
```

---

### HTTP 404 Model Not Found

**症状：**
```json
{"error": {"message": "Model not found: gpt-5"}}
```

**可能原因：**
1. 模型名称拼写错误
2. 未配置模型映射
3. Provider 不支持该模型

**解决方案：**
```yaml
# 检查 config.yaml 中的模型映射
model-mapping:
  gpt-4: claude-sonnet-4-5-20250929
```

---

### Connection Refused

**症状：**
```
curl: (7) Failed to connect to localhost port 8317: Connection refused
```

**可能原因：**
1. 服务未启动
2. 端口配置错误
3. 防火墙阻止

**解决方案：**
```bash
# 检查服务状态
systemctl status cli-proxy-api

# 检查端口监听
netstat -tlnp | grep 8317

# 启动服务
cli-proxy-api --config config.yaml
```

---

### Address Already in Use

**症状：**
```
Error: listen tcp :8317: bind: address already in use
```

**可能原因：**
1. 另一个实例正在运行
2. 其他程序占用端口

**解决方案：**
```bash
# 查找占用端口的进程
lsof -i :8317

# 终止进程
kill -9 <PID>

# 或更换端口
# 修改 config.yaml 中的 server.port
```

---

### Token Unavailable

**症状：**
```
Error: OAuth token unavailable or expired
```

**可能原因：**
1. 从未登录
2. 凭证文件被删除
3. Refresh token 也已过期

**解决方案：**
```bash
# 重新登录
cli-proxy-api --claude-login

# 检查凭证目录
ls -la ~/.cli-proxy-api/auths/
```

## VPS 远程认证

在无 GUI 的服务器上进行 OAuth 登录：

### 方法 1: SSH 隧道

```bash
# 本地机器：建立 SSH 隧道
ssh -L 54545:127.0.0.1:54545 user@vps-ip

# VPS 上：执行登录
cli-proxy-api --claude-login

# 在本地浏览器打开认证 URL 完成登录
```

### 方法 2: 本地认证后复制凭证

```bash
# 本地完成认证
cli-proxy-api --claude-login

# 复制凭证到 VPS
scp -r ~/.cli-proxy-api/auths user@vps:~/.cli-proxy-api/
```

## Token 刷新问题

### 手动刷新 Token

如果自动刷新失败，可以手动重新登录：

```bash
# 删除旧凭证
rm -rf ~/.cli-proxy-api/auths/claude/

# 重新登录
cli-proxy-api --claude-login
```

### 检查 Token 有效期

```bash
# 查看凭证文件
cat ~/.cli-proxy-api/auths/claude/default.json | jq '.expiresAt'

# 转换时间戳
date -d @$(cat ~/.cli-proxy-api/auths/claude/default.json | jq '.expiresAt / 1000')
```

## 性能问题

### 响应慢

**可能原因：**
1. 网络延迟
2. Provider API 响应慢
3. Token 刷新中

**解决方案：**
- 检查网络连接
- 使用更近的 Provider
- 预先刷新 Token

### 内存占用高

**可能原因：**
1. 大量并发请求
2. 日志文件过大

**解决方案：**
```bash
# 清理日志
rm -rf logs/*.log

# 限制并发
# 在 config.yaml 中配置限流
```
